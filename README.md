# 赤壁烽火 · Red Cliffs Ablaze

A browser demo of an arcade-style, side-scrolling brawler set in the Three Kingdoms era.
You play 关羽 Guan Yu, fighting across the burning, chained Wei fleet at 赤壁 Red Cliffs to
reach its commander, 于禁 Yu Jin.

This is a vertical slice: **one hero, one stage, four enemy types and one boss**, playable
from the title screen to the stage-clear tally.

This is a sample project developed by Fable 5.2 as a baseline to compare with other games
developed with different loop engineering framework.

**Play it in your browser: https://dynasty-wars-demo.pages.dev**

> **Originality.** This is an original game in the belt-scroll brawler genre. The setting and
> people come from history and the novel *Romance of the Three Kingdoms*. All sprites,
> backgrounds, sound effects and music are generated by code in this repository; nothing is
> taken from any commercial game.

## Controls

| Key | Action |
| --- | --- |
| Arrows or `W` `A` `S` `D` | Move |
| `J` (or `Z`) | Attack. Keep tapping for the 4-hit combo |
| `K` (or `X`) | Jump. `J` in the air for a jump slash |
| Double-tap `←` or `→` | Dash. `J` while dashing for a sweep |
| Walk into an enemy | Grab. `J` to strike (3 times), direction + `J` to throw |
| `J` + `K` together | 青龙斩 Dragon Cleave: invincible spin that costs health when it connects |
| `Enter` (or `Space`) | Start, confirm, continue |
| `P` (or `Esc`) | Pause |
| `M` | Mute |

Tips: attacks only connect on your lane, so line up before swinging. Enemy and boss attacks
all have a wind-up pose. Sidestep the boss's charge and punish his recovery. Food from crates
restores health (包子 steamed bun, 烤鸡 roast chicken); oil barrels explode and hurt everyone.

## Deployment (Cloudflare Pages)

Live at **https://dynasty-wars-demo.pages.dev**

The site is a Cloudflare Pages project named `dynasty-wars-demo`, deployed by uploading the
static `dist/` folder directly. It uses no Git integration, functions, bindings or environment
variables, and the repository contains no Cloudflare-specific files.

To publish a new version, sign in once with `npx wrangler login`, then:

```bash
npm run build
```

```bash
npx wrangler pages deploy dist --project-name dynasty-wars-demo --branch main
```

`--branch main` matters: `main` is the project's production branch, and a deploy from any other
Git branch without it only creates a preview URL.

If you connect the repository to Pages for automatic builds instead, use build command
`npm run build`, output directory `dist`, and Node 20 or newer.

Asset URLs are relative (`base: './'`), so the site also works from a sub-path.

## How it is built

- **Stack:** Vite + TypeScript, Canvas 2D, Web Audio. No runtime dependencies.
- **Resolution:** 384x224, scaled by whole numbers with nearest-neighbour filtering; 60 Hz fixed step.
- **Simulation (`src/sim`)** is headless and deterministic: `step(world, buttons)` returns a new
  world and a list of events and never modifies its input. It has no access to the DOM, clock
  or `Math.random` (enforced by `tsconfig.sim.json` and an ESLint rule). Rendering and audio
  only consume the events.
- **Sprites (`src/gfx`)** are drawn by a small software rasterizer: a shared humanoid rig is
  posed from key poses and baked into palette-indexed pixel frames when the game loads. Heads
  are hand-drawn pixel stamps.
- **Audio (`src/audio`)** synthesizes every effect and plays original tracker-style music.
- **Text:** an embedded 5x7 bitmap font for English. Chinese uses the system's CJK font,
  thresholded onto the pixel grid; on a machine with no CJK font the game shows English only.

```
src/core    seeded RNG and math helpers
src/data    tuning constants, fighters, move frame data, stage layout, strings
src/sim     the game rules: state machine, hits, grabs, hazards, AI, stage flow
src/gfx     rasterizer, rig, art data, renderer, HUD, text
src/audio   sound engine, effect recipes, sequencer, songs
src/app     game loop, keyboard, scenes
tests       unit tests, a bot that plays the whole stage, determinism checks
dev         dev-only pages: /dev/sprites.html and /dev/sfx.html
```

### Tests

`tests/e2e/full-stage.test.ts` runs a simple bot through the entire stage without a browser
and requires it to reach the clear state. `tests/e2e/determinism.test.ts` checks that the
same seed and inputs always give the same world.

To review sprite art without a browser, write PNG contact sheets:

```bash
SHEET_DIR=sheets npx vitest run tests/art/contact-sheet.test.ts
```

### Adding content later

- **A hero:** a move table in `src/data/moves/`, an entry in `src/data/fighters.ts`, a pose
  table and skin in `src/gfx/art/`, then offer it on the select screen.
- **A stage:** a `StageDef` in `src/data/stages/` (sections, waves, props, hazards) and a
  backdrop painter in `src/gfx/render/`.

## Known limits of the demo

- Keyboard only; no gamepad or touch controls.
- Single player, one hero, one stage.
- The art is generated by code, so it is cleaner and simpler than hand-drawn arcade sprites.
- Combat balance was tuned with an automated bot; expect it to want a pass after real play.
